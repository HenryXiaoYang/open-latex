# Engine protocol (fast paragraph server)

Status: **v1 (frozen in M5)**. Requests are JSON lines; responses are framed, with compile
results carrying a JSON header followed by the binary display list (docs/DISPLAY_LIST.md).

## Process

The host spawns `lualatex -interaction=batchmode --output-directory=<work> <work>/lode-serve.tex`
with the project directory as working directory and these environment variables:

| Variable | Purpose |
|---|---|
| `LODE_RESP` | path of a FIFO the server opens for writing responses |
| `TEXINPUTS`, `LUAINPUTS` | prepend lode's `tex/latex//` and `tex//` so `lode-serve.lua`, `lode-dl.lua`, `lode-json.lua` are found |
| `openout_any=a` | allow writing to the FIFO by absolute path |
| `max_print_line=100000` | keep log lines unwrapped for diagnostics |

`lode-serve.tex` is generated by the host: the project's preamble (everything before
`\begin{document}`), then `\newbox\lodebox`, `\begin{document}` and a `\directlua` call that
enters `lode_serve.run(boxnum)`. The server lives inside the document body, so every
`AtBeginDocument` hook (fontspec, microtype) has run.

Requests travel on the server's **stdin** as JSON, one object per line. Responses come back on
the **FIFO** as frames: `u32 little-endian length` (of everything that follows), `u8 kind`, payload.
Kind 0 is a JSON object. Kind 1 is a compile result: `u32 json_length`, the JSON header, then the
binary display list. stdout is not used because LuaTeX prints its banner there even in batch mode
(ENGINE_NOTES, E5).

The host must open the FIFO's read end exactly once (non-blocking open, then `poll` for the
first frame) before or while the server starts; closing and reopening it loses frames.

## Requests

| op | fields | reply |
|---|---|---|
| `context` | `id` (int), `ctx` (object, see below) | `{"op":"ok","id":…}` |
| `compile` | `req` (int), `ctx` (int), `source` (string, LaTeX paragraph source, may contain newlines) | `result` frame or `fatal` |
| `ping` | — | `{"op":"pong"}` |
| `stats` | — | `{"op":"stats","requests","font_nextid","node_mem","grouplevel","nest","luastate"}` |
| `shutdown` | — | `{"op":"bye"}`, then the process ends |

### Context object

Produced by `lode-capture` for each paragraph and forwarded verbatim:

```json
{ "ints":  {"tolerance":200, "pretolerance":100, "language":0, "lefthyphenmin":2, "...":0},
  "dims":  {"hsize":23592960, "parindent":1114112, "emergencystretch":0, "...":0},
  "glues": {"leftskip":[0,0,0,0,0], "parfillskip":[0,65536,0,2,0], "baselineskip":[891290,0,0,0,0], "...":[]},
  "parshape": null,
  "everypar": "",
  "begin": { "line": 33, "nest": 1, "font": 27,
             "nfss": {"enc":"TU","family":"TeXGyrePagella(0)","series":"m","shape":"n","size":"10.95","baselineskip":"13.6pt"},
             "color": "0 g 0 G", "mathversion": "normal" } }
```

Replay order inside the server (per compile): `\begingroup`, `\global\setbox\lodebox\vbox\bgroup`,
Lua sets every int/dim/glue parameter and `\parshape`, NFSS state is re-selected with
`\fontencoding…\fontsize…\selectfont` (never by raw font id, which differs per process), then the
source lines are fed through `tex.print`, then `\par\egroup\endgroup`. Everything runs inside
one `tex.runtoks` call.

## Responses

### `ready`
`{"op":"ready","banner":…,"luatex_version":124,"fingerprint":…,"font_nextid":…}` — first frame.

### `result` (frame kind 1)
JSON header:
```json
{ "op":"result", "req":7, "ctx":25,
  "status":"ok" | "ok_degraded" | "error",
  "errors":[{"message":"Undefined control sequence","context":"…","line":2}],
  "lines":3, "glyphs":166, "width":22609920, "height":…, "depth":…, "dl_bytes":5055,
  "t_tex_us": 1437, "t_traverse_us": 279, "t_pack_us": 130 }
```
followed by `dl_bytes` of binary display list (paragraph framing; empty when `status` is `error`
and no box was produced).
Error `line` numbers count from the first printed line; line 1 is the replay head, so source line
= `line − 1`. `status:"error"` means TeX reported at least one error while typesetting; a display
list may still be present (TeX recovers in batch mode) but must not be trusted.

### `fatal`
`{"op":"fatal","req":…,"reason":"state_mismatch","before":…,"after":…,"errors":[…]}` — the engine's
state fingerprint (group level, nesting, current font, interaction mode, `\everypar`, catcodes
of the special characters, `\count0–9`, …) changed across the request. The server exits with
status 3 right after sending this; the host restarts it with a new `engine_generation`.

## Display-list items

The binary format is specified in `docs/DISPLAY_LIST.md`; the JSON mirror used by the capture
files and by `lode dl2json` has these item encodings:

| tag | fields | meaning |
|---|---|---|
| `g` | font id, char code, glyph index (null for TFM fonts), x, baseline y, advance width, expansion factor | glyph; renderer scales horizontally by `1 + ef/1e6` |
| `r` | x, top y, width, height | filled rectangle |
| `c` | stack, cmd (0 set, 1 push, 2 pop, 3 current), data | `pdf_colorstack` whatsit (raw PDF color operators) |
| `l` | mode, data | `pdf_literal` (mode −1 = `\special`) passthrough; page becomes Degraded |
| `u` | kind, detail | unsupported node (leaders, non-TLT dir, inserts, adjust, …) |
| `m` | "on"/"off", x | inline math boundary |

All coordinates are scaled points relative to the paragraph box's top-left (fast path) or the
page's top-left (capture pages). Glyph `x` already includes `xoffset`; `y` includes `yoffset`.
